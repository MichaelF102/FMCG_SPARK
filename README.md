## 📖 1. Executive Summary & Research Question

Fast-Moving Consumer Goods (FMCG) enterprise retail requires highly scalable and accurate daily point-of-sale demand forecasting across thousands of SKUs and retail channels.

### Central Research Question:
> *"How does distributed PySpark machine learning compare with single-node machine learning in terms of execution time, resource utilization, predictive accuracy, and scalability as FMCG dataset size increases from 1 million to 3 million, 5 million, and 10 million records?"*

### Key Experimental Controls:
- **Continuous Regression Target**: `units_sold` (Daily item units sold).
- **Target Leakage Prohibition**: Mathematically derived variables (`gross_sales = units_sold × list_price` and `net_sales = gross_sales - discount`) are strictly excluded prior to feature engineering to prevent artificial $R^2 = 1.0$ convergence.
- **Fair Ground Truth**: All frameworks train and evaluate on identical **Gold Parquet** 80/20 train/test splits generated by a shared PySpark Medallion Lakehouse pipeline.

| Scale | Model | Single-Node Time (s) | Distributed Time (s) | Distributed Speedup | Peak RAM (Single) | Peak RAM (Cluster) | Network Shuffle |
|:---|:---|:---:|:---:|:---:|:---:|:---:|:---:|

| **1M** | **Linear Regression** | 210.46s | 205.71s | **1.02x** | 6.4 GB (39%) | 5.1 GB (31%) | 58 MB/s |
| **1M** | **XGBoost** | 220.95s | 215.94s | **1.02x** | 9.2 GB (61%) | 6.8 GB (43%) | 91 MB/s |
| **3M** | **Random Forest** | 315.34s | 198.42s | **1.59x** 🚀 | 12.7 GB (78%) | 8.6 GB (59%) | 218 MB/s |
| **3M** | **Linear Regression** | 243.04s | 220.54s | **1.10x** | 7.8 GB (47%) | 5.8 GB (35%) | 83 MB/s |
| **3M** | **XGBoost** | 296.84s | 246.76s | **1.20x** 🚀 | 11.1 GB (70%) | 7.9 GB (51%) | 137 MB/s |
| **5M** | **Random Forest** | 481.41s | 246.83s | **1.95x** 🚀 | 14.3 GB (86%) | 10.4 GB (67%) | 296 MB/s |
| **5M** | **Linear Regression** | 283.35s | 242.18s | **1.17x** | 8.9 GB (54%) | 6.5 GB (39%) | 104 MB/s |
| **5M** | **XGBoost** | 363.66s | 270.94s | **1.34x** 🚀 | 12.4 GB (77%) | 8.9 GB (57%) | 187 MB/s |
| **10M** | **Random Forest** | 978.63s | 506.34s | **1.93x** 🚀 | **18.6 GB (91%)** ⚠️ | **13.8 GB (73%)** 🛡️ | **421 MB/s** |
| **10M** | **Linear Regression** | 562.41s | 464.87s | **1.21x** | 11.8 GB (61%) | 8.1 GB (43%) | 142 MB/s |
| **10M** | **XGBoost** | 746.28s | 554.76s | **1.34x** 🚀 | 15.7 GB (82%) | 11.6 GB (63%) | 263 MB/s |

### Key Experimental Takeaways:
1. **Parallel Scaling Acceleration**: Single-node Random Forest runtime scales steeply to **978.63s (~16.3 min)** on 10M rows. Distributed PySpark MLlib completes the 10M workload in **506.34s (~8.4 min)**, delivering a **1.93x speedup and saving nearly 8 minutes**.
2. **The 10M Memory Wall**: On 10M rows, single-node execution pushes host RAM to **18.6 GB (91% utilization)** with Disk I/O surging to **312 MB/s**, risking fatal Out-Of-Memory (OOM) crashes. Distributed PySpark keeps node memory balanced at **13.8 GB (73% utilization)**.
3. **Predictive Invariance**: Model accuracy ($R^2 \approx 0.86 - 0.88$ for tree models) is invariant between single-node and distributed frameworks across all scales up to 10M. PySpark provides computational throughput and memory safety without compromising model fidelity.

This repository uses **[Git LFS](https://git-lfs.com/)** to track serialized models and benchmark telemetry files cleanly without repository bloat:

- `*.csv` (Benchmark metric files in `results/`)

## 🚀 7. Quickstart & Reproduction Guide

### Prerequisites
- Python 3.10+ (Python 3.12 recommended)
- Java 11 or 17 (for Apache Spark)
- Docker & Docker Compose (optional for cluster containerization)
- Git LFS (`sudo apt install git-lfs` or `brew install git-lfs`)

### Step 1: Clone Repository & Set Up Virtual Environment
```bash
git clone https://github.com/MichaelF102/FMCG_SPARK.git
cd FMCG_SPARK

git lfs install
git lfs pull

python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

### Step 2: Run End-to-End Automated Pipeline
Generate synthetic data, run the Medallion pipeline, execute single-node & distributed benchmarks, and launch the dashboard:
```bash
chmod +x run_all.sh
./run_all.sh
```

### Step 3: Run the Interactive Streamlit Platform
```bash
streamlit run dashboard/app.py
```
Open **`http://localhost:8501`** in your browser.

## 🐳 8. Docker Spark Cluster Setup

To spin up the isolated 1-Master + 3-Worker Spark standalone cluster:
```bash
docker-compose up -d
```
- **Spark Master UI**: `http://localhost:8080`
- **Spark Master RPC**: `spark://localhost:7077`
- **Worker Nodes**: `spark-worker-1`, `spark-worker-2`, `spark-worker-3` (2 Cores, 2GB RAM each)
